# 퍼즐 축제 연출 강화

퍼즐 규칙과 4번째 스테이지의 45초·25개 목표를 유지하며 축제 연출을 강화했습니다. 농장 관리 기능은 추가하지 않았습니다.

- 시작 시 FESTIVAL TIME 환영 배너, 양쪽 불꽃과 색종이 발사
- 밤하늘에서 주기적으로 터지는 서로 다른 색의 불꽃놀이
- 배경에서 천천히 움직이는 세 가지 무대 조명
- 밝기가 부드럽게 변하는 상단 전구
- 전구와 분홍·보라·청록빛으로 장식한 퍼즐 테두리
- 축제 전용 시작 팝업과 LET’S PARTY 이름표
- 매 조합마다 삼중 빛고리·큰 별·색종이 폭발
- 3콤보 이상 또는 PERFECT 성공 시 추가 불꽃
- 5콤보 이상에서 색종이와 지연 폭발, 8콤보 이상에서 양옆 연속 불꽃
- 피버 진입 시 MEGA FEVER! 배너, 다섯 차례 추가 불꽃과 대량 색종이
- 클리어 화면 위로 이어지는 대형 불꽃과 색종이 피날레
- 실패·재시작·다음 스테이지 이동 시 연출 정리

큰 불꽃은 주로 헤더에, 색종이는 화면 양옆에 배치합니다. 장식은 터치 입력을 받지 않습니다. 게임의 난수와 별도의 시각효과 난수를 사용해 타일 생성·점수·시간 계산에 영향을 주지 않습니다.

모바일 부하를 제한하기 위해 캔버스 입자는 최대 520개, 대기 중인 연쇄 효과는 최대 24개, 갱신은 약 30fps, 해상도 배율은 최대 1.5로 제한했습니다. 메뉴·화면 숨김 시 애니메이션을 정지합니다. 동작 줄이기 설정에서는 정적인 축제 장식만 표시합니다.

검증: 기존 133개 회귀 검사 및 새 축제 연출 17개 검사 통과. 시작·피버·클리어·일시정지·재개·스테이지 전환·입자 및 연쇄 효과 상한·매 조합 폭발·클리어 화면 레이어·난수 분리·동작 줄이기를 확인했으며 320px/390px 화면에서 환영 배너가 게임 현황을 가리지 않는지 확인했습니다.

현재 버전: `festival-mega-4`. 입자를 크게 하고 가산 합성으로 빛을 강화했으며, 불꽃 간격을 0.7초로 줄였습니다. 네온 테두리와 무대 조명도 강화했습니다. 전체 화면 섬광이나 퍼즐판 흔들림 없이 폭발감을 표현합니다. 총 150개 검사 통과.


## 파괴 효과와 모바일 부하 개선 — festival-shatter-5

일반·축제 조합에 8개의 큰 파편을 추가했습니다. 축제의 조합 이펙트는 캔버스가 별과 빛고리를 담당하고, HTML 효과는 파편·섬광·소수의 장식으로 제한합니다. 고콤보에서도 즉시 생성되는 HTML 효과는 15개이며 지연 꽃잎 효과를 중복 생성하지 않습니다.

캔버스 입자 상한을 520개에서 360개로, 해상도 배율 상한을 1.5에서 1.25로 줄였습니다. 빛 번짐 이미지는 색상별로 생성해 재사용합니다. 배경 불꽃 간격은 1.1초, 추가 콤보 불꽃 최소 간격은 0.35초이며 조합 위치의 폭발은 매번 표시합니다. 큰 조명의 blur와 테두리 filter 애니메이션을 제거했습니다.

검증: 기존 133개 및 축제 19개 검사, 총 152개 통과. 실제 휴대폰 프레임 속도는 측정하지 않았으므로 기기별 끊김 개선 정도는 추가 체감 확인이 필요합니다.


## 축제 전용 끊김 수정 — festival-smooth-6

이번 수정은 상시 렌더링을 없애는 구조 변경입니다. 시작·조합·피버·클리어 때만 짧게 캔버스를 켜며, 입자와 배너가 끝나면 requestAnimationFrame을 종료하고 캔버스를 숨깁니다. 배경 불꽃 자동 생성, 대형 조명/전구 애니메이션, 축제의 장판 전체 필터와 중복 콤보 파동을 제거했습니다. 정적인 야간 배경·전구·네온 테두리와 매 조합의 파편 8개는 유지합니다.

- 동시 입자 상한 360 → 96개. 느린 프레임이 이어지면 해당 스테이지 동안 48개로 낮추고 추가 배경 효과를 생략합니다.
- 별은 미리 그린 작은 이미지를 재사용합니다. 매 프레임 별 꼭짓점을 계산하거나 가산 합성 모드를 변경하지 않습니다.
- 조합 HTML 효과는 파편 8개만 생성합니다. 캔버스가 짧은 빛고리와 별빛을 담당합니다.
- 피버가 시작되면 기존 장식 입자를 정리합니다. 큰 콤보 장식도 마일스톤에서만 생성하고, 대기 효과는 최대 4개로 제한합니다.
- 캔버스는 CSS 픽셀 해상도로 그립니다. 입력 위치·퍼즐 규칙·점수·시간은 변경하지 않습니다.

검증: 회귀 133개 + 축제 23개 = 156개. 쉬는 동안 렌더 루프가 없는지, 첫 입력에 다시 반응하는지, 메뉴·스테이지 이동 정리, 저속 환경의 자동 입자 감소를 검사했습니다.

### 동일 조건의 렌더링 비교

390×844 모바일 뷰포트, DPR 3, Chromium CPU 4배 감속. 3.5초 준비 후 1.2초 대기 측정, 이후 5초 동안 0.4초 간격으로 같은 조합·피버 연출을 실행했습니다. 실행 스크립트: `tests/festival-performance.cjs`. 아래는 별도 브라우저 테스트가 실행되지 않는 상태에서 측정한 한 번의 전후 비교입니다.

| 축제 측정값 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| 대기 1.2초의 캔버스 지우기 호출 | 36회 | 0회 |
| 연속 조합 5초의 스크립트 실행 시간 | 423ms | 101ms |
| 같은 구간의 메인 스레드 작업 시간 | 4165ms | 1145ms |
| 프레임 간격 95백분위 | 50ms | 17ms |
| 50ms를 넘은 프레임 | 6회 | 0회 |

이는 개발 환경의 합성 렌더링 부하 비교이며 실제 Android 기기의 FPS 보장이 아닙니다. 일반 스테이지는 비교 측정에서 프레임 간격 95백분위 33ms로 전후 동일했습니다. 스테이지 진행과 실제 입력 처리는 별도의 회귀 검사로 확인했습니다.
