# 2차: 나비 선택과 만개 축제

작업 시작 시 최신 main은 `1561267`이며 1차 PR이 미병합 상태였다. 1차 커밋 `ce4223c` 위에서 확장했다. 기존 24개 인라인 이미지 데이터, 콤보 연출, +0.2초와 +8초 상한, BLOOM 8콤보/5초/1.5배, PERFECT, 일반 랜덤 70/20/10을 유지한다.

- 나비는 현재 합성 가능한 이웃이 있는 일반 봉오리에 최대 한 마리만 앉는다. 재생성 중인 칸과 손가락으로 누르고 있는 칸은 후보에서 제외한다. 상대 재료나 정답 경로는 표시하지 않는다.
- **다른 색 → 나비 칸**으로 합성할 때만 기존 최종 점수에 ×2를 한 번 적용한다. 출발점이면 보너스 없이 사라진다. 나비는 시간을 추가하지 않는다. 같은 색 실패는 콤보만 끊고 나비는 유지한다.
- 등장: 첫 6–10초 이후이며 최소 2개화, 이후 획득/소멸부터 8–14초. 수명 7초, 마지막 1.5초만 약한 날갯짓. 후보가 없으면 판을 바꾸지 않고 1초 뒤 재검사한다.
- 메뉴/백그라운드 정지는 나비 등장과 수명도 보존한다. 개발자 타이머 정지는 기존처럼 게임 제한시간만 멈춘다. 합성/생성/재색칠/세대 변경/재시작/종료/클리어에서 내부 상태와 DOM을 함께 정리한다.
- 보너스 안내는 수확 표시줄에 1초 동안 나타난다. 작은 비행 효과는 0.55초이며 입력을 막지 않는다. reduced motion에서는 비행/날갯짓/진동을 생략한다. 나비 단독 성공 진동 10ms; 콤보 성공은 기존 진동을 그대로 사용한다.
- ST에 `type`, `goalType`, `totalGoal`, `spawnTuning`을 추가했다. 기존 일반 5개는 보존하며 3개 일반 스테이지 다음, ST4에 만개 축제를 넣었다. 기존 ST4/5는 ST5/6이다.
- 만개 축제: 기본 45초, 모든 꽃 합산 25송이, 즉시 클리어. 초기 요구 속도는 약 1.8초당 한 개화이며 기존 380ms 재생성 시간보다 여유가 있다. 실제 난이도는 모바일에서 조정한다. 콤보 시간 보너스는 계속 적용된다.
- 축제 랜덤: 자연 55%, 목표 균형 20%, 체인 기회 25%, 체인 가중치 1.2. 모든 색의 확률을 유지하며 BLOOM 진입 기준 자체는 변경하지 않는다. 모든 꽃은 목표 점수 기본 100점 대상이다.

주요 함수: `scheduleButterfly`, `spawnButterfly`, `updateButterfly`, `collectButterfly`, `clearButterfly`, `resetButterfly`, `butterflyFlight`, `renderButterflyHint`, `totalGoalStage`. 기존 `merge`, `spawn`, `paintBud`, `ui`, `done`, `goalText`, 메뉴/종료/개발자 처리를 확장했다.

밸런스는 `BUTTERFLY_*`, `FESTIVAL_DURATION=45`, `FESTIVAL_TOTAL_GOAL=25`, `FESTIVAL_SPAWN_TUNING`에 모았다. 나비 시스템은 단일 상태 구조로 최대 한 마리를 지원한다.

## 빠른 테스트

메뉴 → 개발자 모드 → 만개 축제 → 시작하기 → 나비 생성 → 패널 닫기. 나비가 있는 칸으로 합성하거나 반대 방향으로 사용해 차이를 확인한다. STAGE 버튼 길게 누르기로도 개발자 패널을 연다.

Playwright 환경에서 아래를 순서대로 실행한다. 기존 문서의 `CHROME_PATH` 설정을 사용할 수 있다.

```text
node tests/bloom-regression.cjs
node tests/butterfly-festival.cjs
```

1차 25개와 2차 41개 검사가 통과했다. JS 문법, 브라우저 런타임/콘솔, 실제 Chromium 터치 이벤트, 320×568 / 360×740 / 412×915 화면, reduced motion, 수명/메뉴 정지, 배율 중첩, ghost 정리, 총 개화 및 다음 스테이지를 검증했다. 인라인 이미지 24개의 SHA-256이 1차와 동일하다. 1차의 밸런스 선언 및 8개 콤보/BLOOM 연출 함수도 동일하다.

남은 기술 부채: 기존 제한시간의 setInterval 지연 가능성, 개발자 목표 변경의 ST 직접 수정. 나비 이모지 모양은 OS별로 달라질 수 있다. Android 실기기에서 나비 발견성, 방향 이해, 진동, 빠른 연속 입력과 프레임, 나비와 콤보 사이의 선택 빈도를 확인해야 한다.
