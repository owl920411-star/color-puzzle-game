# 크레용블룸 — 출시 전 MAIN 단일 작업 기준

사용자 결정: 출시 전까지 MAIN에서 수정·배포하고 하나의 실제 서비스 주소로 테스트한다. DEV/Preview 전환은 사용자 필수 절차에서 제외한다. 기존 DEV와 기록은 삭제하지 않는다. 이 문서는 과거 인계서의 DEV 우선 배포 정책을 대체한다.

## 보존과 이번 수정

기존 MAIN: `45b8e72b09183f5d7aae4a8d7f7cd62f1c922a1b`. 백업 브랜치: `backup/main-before-unification-20260926`.
현재 기능 기준: DEV `c8ecf9f8f6adc3ba8f84b5c484d12144b08f861c`. 기존 MAIN은 이 커밋의 조상이며 이력 강제 덮어쓰기를 하지 않는다.

WORLD 2A에서 지운 마스코트의 `if(mascotTime>0&&(mascotTime-=dt)<=0)`가 update() 끝에 남아 있었다. 이는 일반·모래에서 ReferenceError를 발생시키고 다음 프레임 예약까지 중단시킨다. 변수만 임시로 재선언하지 않고 남은 조건문을 제거한다.
GitHub의 WORLD 1(`e282f487...`)과 현재 DEV 비교에서 endless-app.js의 유일한 차이는 위 조건문 추가 한 줄임을 확인했다. 따라서 해당 파일을 기존 blob `ba909168070153f3389162b5a3e0c92d4a1c6a40`으로 복구하는 것이 그 조건문만 제거하는 것과 동일하다. 그래픽·CONTROL 17·점수·난이도 코드를 통째로 과거 버전으로 되돌리는 작업이 아니다.

HTML에는 `CB-MAIN-1` 메타와 `CRAYON BLOOM · MAIN 1 · CONTROL 17` 표시를 추가한다. 앱/CSS 쿼리 버전을 cb-main-1로 변경하고 `쏙!` 버튼을 유지한다. 게임판·오른쪽 버튼 크기와 배치는 변경하지 않는다. 기존 저장 키는 유지한다. 브라우저 저장 데이터는 사이트 주소별로 다르므로 DEV 기록이 운영 주소로 자동 이전된다고 보장하지 않는다.

## 이번에 실행한 검증과 한계

`tests/main-runtime.test.cjs`: 12개 통과. 이번 환경에서는 GitHub에서 읽은 실제 update/frame 함수 발췌본을 LOCAL_APP_SOURCE로 지정해 Node VM에서 실행했다. 정상판과 WORLD 2A 문제 조건문을 넣은 버전을 비교했다. 일반·모래 각각 180프레임의 갱신 지속, 정지, 점수 갱신, 줄 제거 단계와 효과 정지 경로를 검사한다.

이 테스트의 DOM·렌더링·엔진은 대체물이다. 전체 앱의 실제 엔진 통합 검사나 실제 휴대폰 플레이는 아니다. 이전 96/117개 결과를 이번 버전의 전체 재검사 결과로 재사용하지 않는다. 실제 사이트 접속은 이 도구 환경에서 제한되어 별도 확인이 필요하다. 12개 통과를 전체 게임 정상·출시 가능 판정으로 설명하지 않는다.

## 앞으로의 완료 기준

코드 변경, MAIN 반영, 해당 커밋의 Cloudflare Production 빌드 성공, 실제 사이트 실행 확인을 별개 상태로 보고한다. GitHub Actions 실행 0개를 Cloudflare 빌드 없음으로 해석하지 않는다. Cloudflare GitHub App check-runs와 Production 대상까지 확인한다. 실제 URL은 dashboard/build 출력에서 확인한 것만 사용하고 Worker 이름을 조합해 추측하지 않는다.

매 배포는 작은 변경 단위로 수행하고 버전 표기를 함께 올린다. 오류가 있으면 이전 정상 코드를 새 커밋으로 복구한다. 큰 기획·마스코트 일러스트 자산화는 별도 작업이며 이번 실행 복구와 섞지 않는다. 정식 마스코트가 적용되었다고 주장하지 않는다.

출시 직전에는 출시 후보 버전을 고정해 안정화한다. 복수 브랜치·테스트 환경의 재도입은 필요할 때 정하며 사용자에게 자동으로 강제하지 않는다.
