# Single-touch release window

## Reason for CONTROL23 change
User reported one touch moving two cells. Existing behavior reproduced: 205/220ms single touches moved twice, 250ms three times. This request explicitly authorizes investigating and correcting that sensitivity.

Only the delay after the first stationary move changes: 38ms -> 100ms. First move/hold confirmation remains 165ms; subsequent ramp remains 33ms then 29ms. Second movement now starts at 265ms rather than 203ms. Quick tap release, deliberate double taps, swipe threshold/timing, buttons, keyboard, rules, audio, visuals, and saves are unchanged. Seven-cell hold traversal increases by 62ms, from 352ms to 414ms.

The touch-and-buttons freeze checksum is renewed for this documented exception only; all other frozen spans are unchanged. Timing assertions remain exact, the boundary sweep expands through 350ms, and tutorial observation uses a longer hold to still verify three actual observed moves.

## Validation
- Release regression: 893/893 passed.
- Deterministic single touch: 100/180/205/220/250ms => one move; 265ms => two. Release stops timers.
- Real Chromium CDP touch: 30 single touches across left/right and 40/120/205/220/240ms => one cell each; deliberate double taps => two cells.
- Real touch checks: quick CW/CCW swipes, hold followed by horizontal drift (no rotation), vertical HOLD/drop after holding, release stops.
- Regression includes multitouch drop, wall behavior, pause/resume, tutorial, storage, storybook and game rules.
- Physical Android touch feel remains unverified. User should tap once on each half, deliberately tap twice, and hold; expected one cell, two cells, then continuous smooth movement.
