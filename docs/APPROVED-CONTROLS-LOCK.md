# 사용자 승인 조작 잠금 · 2026-10-04

사용자가 현재 조작감을 승인했다. 기준은 `00edfd6bf96522d7db58cd7bd25293b57c1dded4`
(`CB-RC2-HOLD-START1`)이며 이번 잠금은 게임 파일을 수정하지 않는다.

- 짧은 터치: 손을 떼는 즉시 해당 방향 한 칸.
- 정지 롱프레스: 232ms 첫 이동, 265ms 두 번째 이동, 이후 29ms 간격.
- 빠른 좌우 스와이프: 기존 165ms 창과 회전 방향 유지.
- 위 HOLD, 아래 DROP, 물리 버튼, 멀티터치, 벽·충돌, 취소·일시정지와 블록 교체 유지.

## 잠금 범위

`docs/approved-controls-lock.json`은 컨트롤러와 입력 엔진, 회전 규칙, 버튼 중복 입력 방지 모듈의 전체 SHA-256을 고정한다.
컨트롤러 파일 안의 빈 영역에 별도 입력을 추가하는 우회도 전체 파일 해시로 감지한다.
기존 부분 동결 검사도 유지한다. 다른 기능은 별도 모듈에서 작업하되 승인된 입력을 대체하지 않는다.

`AGENTS.md`는 사용자 명시적 잠금 해제 없이는 조작·기준·검사를 변경하지 못하도록 지시한다.
PR CI는 **변경 전 main**에서 검사 코드와 기준을 가져온다. PR 안의 검사 파일을 실행하지 않으며,
잠금 기준·검사·워크플로·기존 조작 테스트를 바꿔서 통과시키는 것도 거부한다.

```sh
node scripts/check-control-lock.cjs
node scripts/test-rc.cjs
```

## GitHub 병합 강제 차단

main 브랜치 보호에서 PR 필수, 필수 상태 검사 `Approved controls`, 관리자 포함 우회 금지,
강제 푸시 금지와 삭제 금지를 적용해야 실패한 변경의 병합을 GitHub가 차단한다.
CI를 추가한 것과 브랜치 보호를 설정한 것은 다르다. 실제 설정을 확인하기 전에는 강제 차단 완료라고 보고하지 않는다.
잠금 파일을 고쳐야 하는 PR은 검사 실패가 정상이다. 먼저 사용자의 새 명시적 해제 지시가 필요하다.

저장소 소유자는 권한으로 브랜치 보호를 해제할 수 있다. 코드만으로 소유자의 모든 변경을 영구히 막을 수는 없다.
이 장치는 승인된 조작의 실수·무단 수정과 검사 기준을 같이 바꾸는 우회를 막기 위한 것이다.
