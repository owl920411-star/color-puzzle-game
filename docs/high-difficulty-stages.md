## 스테이지

기존 ST1–6의 목표, 시간, 생성 보정과 만개 축제를 보존했다. 총 15개이며 10번 속도 압박 뒤 11번에서 숨을 돌린다.

| 2 | EASY | 주황 10 | 60초 |

콤보 목표는 `maxCombo`로 판정한다. 달성 후 다른 꽃/실패로 현재 콤보가 끊겨도 달성 표시가 유지된다. 꽃 목표와 콤보 목표가 모두 완료되면 즉시 클리어한다. 챌린지는 꽃 수가 클리어 조건이 아니다.

일반 목표는 기존 목표 개화 100점/비목표 45점을 유지한다. 축제와 챌린지는 모든 꽃이 목표 점수 대상이다. PERFECT → 콤보 → 기존 반올림 → BLOOM 및 정수 반올림 → 나비 ×2 순서를 유지한다. 나비는 선택 사항이며 어느 스테이지에서도 필수 목표가 아니다.

## 밸런스 구조

ST 필드: `type`, `goalType`, `g`, `t`, `a`, `difficulty`, `randomProfile`, `butterflyEnabled`, 선택적 `comboGoal`, `totalGoal`, `spawnTuning`.

| DIFFICULTY_PROFILES | 자연 / 목표 / 체인 |
| --- | --- |
| EASY / NORMAL | 70 / 20 / 10% |
| HARD | 78 / 14 / 8% |
| EXPERT | 83 / 10 / 7% |
| PRESSURE | 55 / 22 / 23%, 체인 가중치 1.2 |
| COMBO | 60 / 15 / 25%, 체인 가중치 1.2 |

EASY/NORMAL 비율은 기존 초반 손맛 보존을 위해 동일하며 기존 스테이지별 `a` 차이를 유지한다. 축제는 기존 `spawnTuning` 55/20/25가 우선한다. 모든 프로필에서 모든 색의 확률은 양수다.

주요 새 상수: `PRESSURE_DURATION=38`, `CHALLENGE_DURATION=42`, `CHALLENGE_COMBO_GOAL=7`, `EXPERT_DURATION=50`, `EXPERT_COMBO_GOAL=7`, `DEAD_BOARD_THRESHOLD=0`, `DIFFICULTY_PROFILES`. 개별 목표와 시간은 ST에 모았다.

DEAD BOARD 복구는 실제 인접 조합 0개이고 전체 36칸 재생성이 끝났으며 누르고 있는 손가락이 없을 때만 동작한다. 나비 칸을 피해서 한 칸만 다른 색으로 교체한다. 전체 판을 섞지 않고 점수/시간/목표/현재·최고 콤보를 변경하지 않는다. 시작/재생성 완료/게임 루프에서 확인하며 일시 정지·클리어 중에는 실행하지 않는다.

## 화면과 개발자 기능

콤보 목표는 미션 영역의 별도 줄에 표시해 현재 콤보와 구분한다. 시작 화면에서 꽃 목표·콤보 목표·시간을 모두 보여준다. 실패 결과에는 목표 진행, 최고 콤보, 부족한 꽃/콤보를 표시하고 한 송이 또는 최고 콤보 한 단계 차이를 짧게 알려준다.

개발자 패널: 번호로 ST 이동, HARD, EXPERT(마지막 ST), RUSH, COMBO 바로가기. 현재 프로필과 색별/전체 인접쌍도 표시한다. 기존 나비 생성·축제·시간·목표 조작은 유지한다.

주요 함수: `flowerGoalDone`, `done`, `stageName`, `randomBalance`, `recoverDeadBoard`, `remainingGoalText`, `resultTitle`; 기존 `ui`, `goalText`, `spawn`, `merge`, 나비 사용 여부, 개발자 조작과 스테이지 전환을 확장했다.

## 검증과 남은 확인

```text

```

기존 25개 + 나비/축제 41개 + 고난도 57개 = 123개 검사 통과. 인라인 JS 문법, 브라우저 런타임/콘솔, Chromium touch, 모션 감소, 320×568 / 360×740 / 412×915 화면, 기존 6스테이지 보존, 목표 영속성, 즉시 클리어, dead 복구, 나비/BLOOM, 실패/재도전/마지막 스테이지 순환을 검증했다.

자체·추가 코드 검토에서 고난도 목표 HUD가 커질 때 스테이지 전환 직후 하단이 밀리는 버그를 찾아 `begin`/`prepareStage` 뒤 보드 크기 재계산으로 수정했다. 해당 실제 전환 경로에 회귀 검사도 추가했다.

123개 검사는 기능 정확성을 확인하며 사람의 클리어율을 보장하지 않는다. 러시는 약 1.58초당 한 송이, 최종 EXPERT는 약 1.67초당 한 송이와 7연속 판단을 요구하는 초기값이다. 입력/재생성 시간상 가능한 수치지만 실제 Android 손맛과 난이도 곡선은 반복 플레이로 조정해야 한다. 기존 제한시간 setInterval 지연 가능성, 개발자 목표 변경이 ST를 직접 수정하는 구조는 남아 있다. 나비 이모지의 OS별 차이도 실기기에서 확인한다.
