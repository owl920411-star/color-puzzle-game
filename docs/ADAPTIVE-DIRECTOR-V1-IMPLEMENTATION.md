## 적용의 첫 단계

처음에는 `관찰만`이 기본이다. 플레이는 CONTROL 16 / NOVICE 7 / BLOCK ITEMS V2 규칙 그대로이고, Director는 판단 이유만 만든다. 지반 상승은 3분부터 시작한다. 점수 증가 아이템을 복원하지 않는다. 오른쪽 버튼 배치와 큰 즉시하강 버튼을 유지한다.

별도의 설정 화면에서 `자동 조절`을 선택하면 **다음 새 판부터** 실제 지반 주기를 제한적으로 바꾼다. 현재 판의 설정을 중간에 섞지 않는다. `끄기`는 새 판의 계측·학습·적응형 조절을 끈다. 이전에 저장한 개인 자료는 별도 확인형 초기화로 삭제한다.

`편안하게`는 기본 주기보다 빠르게 하지 않는다. `균형`은 더 빠른 도전과 회복을 모두 허용한다. `도전`도 안전한 완화 범위와 공통 하한은 지킨다. 이는 새 난이도 모드 규칙이며 성적에 따라 숨겨서 플레이어의 선택을 바꾸지 않는다.

## 구현 구조

`dist/adaptive-director.js`는 보드 측정·관찰·판정·프로필 요약을 담당하는 순수 모듈이다. DOM, 네트워크, 점수 변경, 게임 시계 소유권이 없다. `takeInterval`은 이미 진행 중인 상승 시간을 수정하지 않고 **새 주기를 예약할 때 사용할 숫자만 반환**한다.

`dist/adaptive-bridge.js`는 기존 게임과 연결할 사건 인터페이스, 설정/진단 화면, 제한된 브라우저 저장을 담당한다. 연결 대상은 실제 블록 고정, 자연 줄 제거, 지반 상승, 아이템·보조 유물 변경이다. 점수판의 숫자 변화만 읽어서 고수를 추정하지 않는다.

`tools/apply_adaptive.py`는 현재 DEV의 검증된 원본 파일에 정확한 사건 연결을 추가한다. 기본 동작은 검사만 하며 `--apply`를 명시해야 파일을 쓴다. dev 브랜치와 두 원본 blob이 모두 일치하지 않으면 정지한다. 수정한 전체 파일을 JavaScript 구문 검사한 후에만 쓰며 원래 제스처 처리 구간의 바이트가 보존되는지 검사한다. 커밋·push·Cloudflare 배포는 수행하지 않는다.

## 관찰과 판단의 근거

유효 입력이 있었고 정상 프레임으로 진행된 실제 고정 배치만 속도 판단 자료로 쓴다. 같은 버튼의 무효 연타, 메뉴와 일시정지, 줄 제거 애니메이션 구간은 처리 속도를 높이는 근거가 아니다. HOLD는 실제 배치를 끝내지 않기 때문에 보관 전후 시간을 같은 배치 사건으로 묶는다. 프레임이 100ms를 초과하는 경우 그 구간과 관련 배치의 신뢰도를 낮추고 예약된 상승을 취소한다.

막힌 빈칸은 블록을 고정하기 직전의 보드와 고정 후 자연 제거만 반영한 보드를 비교한다. 아이템으로 추가 제거된 칸과 줄은 자연 줄 제거 성과에 더하지 않는다. 지반이 올린 높이도 플레이어가 방금 쌓은 높이로 계산하지 않는다. 아이템의 회복은 실제 현재 부담 감소로 남기되 처리 능력 급상승의 증거로 삼지 않으며, 30초 동안 추가 상승을 보류한다.

평소 실력의 대용 지표와 현재 부담은 구분한다. 프로필에는 비슷한 DESERT 레벨, 낙하 간격 구간, 실제 적용 주기 구간별 배치 속도·자연 제거율·추가 빈칸을 저장한다. 정상 게임오버이며 최소 관찰량을 채운 구간만 천천히 갱신한다. 종료 한 번으로 초보/고수 등급을 내리지 않는다. V1에서는 이 장기 프로필을 진단용 참고로 보여주되 새 판의 시작을 어렵게 바꾸지 않는다. 시작 낙하 프리셋 개인화는 후속 검증 대상으로 남긴다.

순간적으로 판이 높다는 이유만으로 난이도를 올리거나 실력을 낮게 단정하지 않는다. 여러 번의 유효 배치에서 높은 적재가 지속되면 상승부터 동결한다. 위험 완화는 작은 단계로 제한하고, 회복하기 전에는 완화 예산을 계속 새로 주지 않는다. 이 규칙은 악용 방지의 초기 방어선이지 고의 부진을 완벽히 감별하는 장치가 아니다.

## 첫 구현 수치 — 사람 평균/객관적 실력 기준 아님

| 항목 | 초기값 | 의미 |
|---|---:|---|
| 자료 창 | 최근 90초, 최대 120개 배치 | 저장량/관찰량 상한 |
| 상승 관찰 최소량 | 신뢰할 배치 20개, 게임 관찰 60초, 표본 간 45초 이상 | 초기 보수적 근거량 |
| 새로운 판단 근거 | 새 배치 6개 | 거의 같은 관찰 창을 반복 증거로 세지 않음 |
| 상승 후보 | 24배치/분 이상 + 자연 제거 0.2줄/배치 이상 + 낮고 안정적인 판 | 검증 전 파일럿 기준 |
| 안정 조건 | 현재 높이 ≤12, 평균 새 막힌 빈칸 ≤0.15, 최근 6개 높이 순증 ≤2/빈칸 신설 ≤1 | 단독 속도 신호 차단 |
| 위험 조건 | 최근 유효 배치 중 4회 이상 높이 ≥15 | 즉사 보장이 아닌 완화 검토 신호 |
| 한 번 변화 | 기본 주기 비율 0.05 한 단계 | 여러 제안이 한꺼번에 쌓이지 않음 |
| 변화 후 대기 | 30초와 새 배치 6개 | 과민 반응 억제 |
| 편안하게 | 주기 ×1.00~1.35 | 기본보다 빨라지지 않음 |
| 균형 | 주기 ×0.85~1.35 | 초기 전체 범위 |
| 도전 | 주기 ×0.85~1.15 | 회복 폭을 더 좁게 선택 |
| 고정 안전 하한 | 11초 | NOVICE 7의 MAX 주기를 넘는 가속 방지 |
| 한 회복 구간 완화 | 최대 3단계 | 높은 판을 유지해 무한히 늦추는 것을 제한 |
| 도움/회복 뒤 대기 | 30초 | 얻은 회복을 즉시 압박으로 상쇄하지 않음 |

높이를 낮추며 실제 회복한 경우에만 새 완화 구간을 허용한다. 같은 높은 판을 유지하면 처음 3단계 이후 더 완화하지 않는다. 따라서 예시의 38초→50초는 즉시 적용되는 규칙이나 보장값이 아니다.

최초 기획의 ‘최근 20~30개/60~90초’는 가변 속도 플레이에서도 관찰량을 확보하도록 ‘최근 90초 최대 120개, 상승 최소 20개’로 구체화했다. 빠른 사람은 최근 30개만 보면 관찰 시간이 너무 짧아질 수 있기 때문이다. 변경 이유를 여기 남기며 사람의 평균 실력이라고 주장하지 않는다.

## 저장

새 요약은 `glassfall-adaptive-v1`에 최근 20판, 프로필 문맥 최대 32개, 판별 변경/주기 로그 최대 각 80개를 저장한다. 외부 서버 전송은 하지 않는다. 같은 브라우저를 쓰는 여러 사람이면 프로필이 섞일 수 있으므로 임시 플레이와 초기화 기능을 둔다. 임시는 해당 판의 프로필과 기록 저장을 끄며 다음 재접속의 기본값으로 저장하지 않는다.

기존 일반/모래 최고점과 보조 유물 저장을 삭제하지 않는다. 관찰/끄기는 기존 일반 기록 키를 사용한다. 실제 자동 모드는 `normal-adaptive-v1-<성향>` 키를 사용한다. DESERT 생존 기록도 같은 기준으로 분리한다. 이는 온라인 랭킹 공정성 보장이 아니라 서로 다른 조건을 섞지 않는 로컬 구조다.

중도 종료/재시작은 정상 게임오버로 세지 않는다. pagehide는 잠정 중단 기록으로 저장하고 같은 판을 마치면 덮어쓰므로 중복 학습하지 않는다. 강제 프리셋, 시간 점프, 무적, 강제 아이템은 학습 제외다. 임의 프로필 초기화도 최고점은 지우지 않으며 현재 판의 프로필 재저장을 막는다.

## 검증한 것

실행: `node --test tests/adaptive-*.test.cjs`
결과: **52개 통과, 실패 0**. 원본 통과 로그는 `docs/ADAPTIVE-TEST-RESULTS.txt`에 포함한다.

검사 대상은 새 Director 모듈과 새 Bridge의 사건 인터페이스다. Bridge 테스트는 가짜 게임 포트/DOM으로 동작한다. 빠른 안정 배치, 빠른 부정확 배치, 느린 안정 배치, 한 번의 콤보, 연타, 대기, HOLD, 프레임 정체, 아이템 회복, 지반 변화, 예고 시각 불변, 11초 하한, 단계별 제한, 임시 플레이, 초기화, 저장 실패, 중복 게임오버, 중도 종료, 기록 키 등을 검사했다.

**실제 전체 GLASSFALL 소스를 결합한 회귀 검사, 실제 폰 멀티터치/화면/성능, 사람의 실력 추정 정확도, 7분 생존과 재미 향상은 아직 검증하지 못했다.** 기존의 48개 BLOCK ITEMS 테스트를 이번 적응형 통합에 대해 재실행했다고 주장하지 않는다. 패키지를 DEV 작업공간에 적용한 뒤 반드시 같이 실행해야 한다.

새 모듈의 52개 테스트는 합성 사례·포트 계약 테스트이며 52명의 사람, 52판 인간 플레이, 장기 BOT 통계가 아니다.

## 별도 모듈 검사실

`adaptive-lab.html`은 네트워크 없이 여는 독립 판정 검사실이다. 실제 게임이 아니며 합성 배치 자료를 입력한다. 데스크톱 Chromium의 390×844 화면에서 모드 3종 × 성향 3종 × 사례 8종 = **72개 조합**의 반환값/런타임 오류를 확인했다. 관찰/끄기에서는 실제 주기 38초가 유지됐고, 가속은 자동 모드의 허용 성향·안정 사례에서만 발생했다. 가로 넘침은 없었다. 이 결과는 실제 GLASSFALL 앱의 휴대폰 렌더링 검사와 다르다.

적용기는 main 브랜치와 변경된 원본에서 아무 파일도 쓰지 않고 중지하는 안전 동작을 별도 확인했다. 실제 원본 DEV 전체에 성공 적용하고 통합 검사를 실행한 결과는 아직 없다.

## 한 번에 적용하는 작업 지시

첨부 패키지의 `tools/apply_adaptive.py`를 저장소 바깥에서 실행한다. 저장소의 dev 브랜치를 체크아웃하고 원본이 위 기준과 같은지 검사한다. `--apply` 없이 먼저 검사한 뒤, 통과한 경우에만 `--apply`한다. 적용기가 원본 불일치로 중지하면 강제로 우회하지 말고 새 코드를 비교해 사건 연결을 다시 맞춘다. 테스트가 통과하기 전에는 커밋하거나 배포하지 않는다. CSS/터치 파서/모래 엔진/NOVICE 7 상수는 바꾸지 않는다. 관찰을 기본으로 유지하고, 이 문서의 미검증 항목은 완료 처리하지 않는다.
